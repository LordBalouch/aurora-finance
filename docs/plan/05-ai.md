# Phase 5 — AI tips (Claude API)

**Goal:** useful, grounded advice and plain-language summaries — never invented numbers.
**Done when:** monthly summary, tips and Q&A work; app works fully without an API key; tests use a fake client.

## Principles
- Real transaction data may be sent to the API (owner's decision 2026-11-23); send what the task
  needs, prefer aggregates when they are enough (cheaper, faster). Never log prompts to git/CI.
- The model explains numbers computed by `insights/`; it does not compute them itself.
- Cache responses per month + data hash (cost control). Show what was sent ("What the AI saw").
- Check current model names and SDK usage when starting this phase.

## Owner wish (2026-11-23)
An "Ask AI" button beside every analysis card (KPIs, trends, debt, budget). One click sends that
card's figures plus short context and returns 2–3 concrete tips with the numbers behind them.

## As built (2026-11-23)
- `ai/advisor.py`: `advise(card, title, facts, task)` → summary + max 3 tips via
  `client.beta.messages.create` on `claude-opus-5-5` (`AI_MODEL`), effort `low`, JSON-schema
  output, server-side refusal fallback (`fallbacks="default"`). Answers cached in `AIAdvice`
  by sha256 of model + system + prompt; "Ask again" bypasses the cache.
- `web/ai_cards.py`: one builder per card (overview, month_story, trends, recurring, anomalies,
  money_flow, debt, years, budget). Numbers are recomputed on the server from `insights`;
  nothing numeric comes from the browser. Prompts are ~1 000 characters (a few øre per click).
- "Ask AI" button on every analysis card (`templates/web/_ai.html`), answer with "What the AI
  saw". Without `ANTHROPIC_API_KEY` the button is disabled and says how to turn it on.
- Answers are in `AI_LANGUAGE` (default Norwegian bokmål); the UI stays English.
- Tests use `FakeClient` (records the request, returns a fixed answer): request shape,
  cache, refusal, cut-off JSON, no key, every card end-to-end.

## 5.5 Ask your data — plan (2026-11-24)
A page `/ask/` with one question field. The model answers by calling a fixed set of read-only
tools built on `insights/`, never by writing SQL or computing on its own. Works with Claude
and with a local model (Ollama, which supports tool calls), the same way as the cards.

**Flow:** question → model gets the tool list, today's date and the data range → it calls
tools (max 5 rounds) → the server runs each tool on `transactions_df()` and returns small
JSON → model writes the answer in `AI_LANGUAGE`. The page shows the answer, a chart of the
last tool result, and "What the AI looked up" (each tool call with its arguments and result).

**Tools** (each returns whole kroner, at most ~50 rows):
| Tool | Arguments | Returns |
|---|---|---|
| `monthly_overview` | from, to (YYYY-MM) | income, spending, net per month |
| `spending` | from, to, group?, category? | total and per month |
| `compare_periods` | two from/to ranges | spending per group in both, and the change |
| `top_merchants` | from, to, group?, n | merchants by amount |
| `recurring_payments` | – | subscriptions, cadence, price changes |
| `unusual_months` | – | robust anomalies per group |
| `debt_payoff` | extra per month | months and interest, with and without extra |
| `budget_status` | month | budget, spent and forecast per group |
| `find_transactions` | text, from?, to?, limit ≤ 25 | matching rows (date, amount, text) |

Groups and categories are checked against the real names, and dates against the data range.
A bad argument goes back to the model as a tool error, never as an exception on the page.

### 5.5 as built (2026-11-24)
- `ai/tools.py` (nine tools), `ai/providers.py` (Claude, Ollama, OpenAI-compatible; also used
  by the cards now), `ai/ask.py` (loop, max 5 rounds, the last tool result tells the model to
  answer), `/ask/` page with example questions.
- Tested with gpt-oss:20b on demo data: one lookup per question, 8–30 s. Two fixes came from
  that test: `spending` without a group returns the split per group (the model otherwise
  asked group by group until the round limit), and merchant questions are steered to
  `find_transactions` (it first summed the whole Subscriptions category for "Spotify").
- The cache key includes the instructions and tool descriptions, so a changed tool never
  serves an old answer.
